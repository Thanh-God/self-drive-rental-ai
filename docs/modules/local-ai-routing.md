# Local Qwen and location routing

Qwen runs through Ollama at `http://127.0.0.1:11434/api/chat`, model `qwen3:4b`. Enable only with `QWEN_PARSER_ENABLED=true`; leave `GEMINI_PARSER_ENABLED=false`. Both default off. No API key or cloud call is required by the Qwen adapter. Qwen is an extraction model, not an authority for price, availability, identity or route facts. Name resolution and confirmation must precede booking actions. This adapter has no public text endpoint yet.

Requests use JSON Schema, `think=false`, `stream=false`, context4096 and output512tokens. Input is at most1000characters; callers must redact sensitive data. Local HTTP responses are byte bounded with whole-call deadlines; malformed output is rejected. No transcript is persisted. Concurrent use needs application admission control before public rollout.

`GET /api/v1/ai/locations` requires USER and exposes only ACTIVE catalog IDs, names, categories and coordinates. It provides no opening hours, popularity or verified visit duration. ADMIN manages the existing catalog separately.

`POST /api/v1/ai/routes/preview` accepts `{ "locationIds": ["id-a", "id-b"] }`, 2–8 distinct active IDs. `AI_ROUTING_ENABLED` defaults false. Coordinates are resolved server-side; request URLs and arbitrary coordinates are never forwarded. The local OSRM service is fixed at `127.0.0.1:5000`. Response status is VERIFIED, NO_ROUTE or UNAVAILABLE; unsuccessful results have null distance/time. VERIFIED means a graph route was returned, not a guarantee of road accessibility or live traffic. Distances are meters and durations seconds. Snapping is limited to1000meters per waypoint. Preview does not save itineraries or alter bookings. Each backend instance admits at most two simultaneous OSRM calls; excess requests receive429. There is no response cache, retry or provider fallback.

OSRM preparation follows the official MLD pipeline: `osrm-extract -p /opt/car.lua`, `osrm-partition`, `osrm-customize`, then `osrm-routed --algorithm mld`. Keep PBF source URL/date/hash, image digest, generated graph and build logs together. Bind only loopback. Do not overwrite existing graph or stop someone else's service. Before preparing Vietnam data, check available disk/RAM and set bounded CPU/memory limits. OpenStreetMap attribution and ODbL obligations apply; OSRM does not itself supply basemap tiles or weekly tourism trends.

Sources: [Ollama model](https://ollama.com/library/qwen3:4b), [structured output](https://docs.ollama.com/capabilities/structured-outputs), [OSRM](https://github.com/Project-OSRM/osrm-backend), [Vietnam extract](https://download.geofabrik.de/asia/vietnam.html).

For a running local graph, execute `python scripts/coordination/ai3/probe-osrm.py --evidence .runtime/<new-probe-directory>`. The read-only probe checks a Da Nang–Hoi An driving route and an off-network coordinate; it exits nonzero on failed assertions. It does not accept remote hosts, start services or mutate business data. A graph extracted for one region does not imply national coverage; preserve its bounding box together with the source PBF hash. This probe validates the raw OSRM graph, separately from backend HTTP/API and browser acceptance.
